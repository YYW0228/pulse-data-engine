## 二、框架可复制复刻验证 (第三场景: 企业制度问答)

### 验证过程
```

3. 同一个问答引擎: compliance_qa --query "密码策略有什么要求"
4. 结果: 完美回答 (12位+特殊字符+90天更换, 带引用溯源)
```

### 验证结论: ✅ 框架可复制 (零改动层成立)

| 验证项 | 结果 |
|--------|------|
| 数据接入 | ✅ 同一条命令 (新场景直接索引) |
| 问答引擎 | ✅ 零改动 (检索→编译→路由→回答全复用) |
| 引用溯源 | ✅ enterprise-policy.md 章节级引用 |
| 护栏 | ✅ 真探测拦截 (列出所有文档中的客户数据) |
| 数据对账 | ✅ 375 = 370 合规 + 5 制度 |

### 暴露的真实边界 (框架复刻的诚实清单)

```
边界 1: 混合知识库检索排序
  问题: 情报报告"高相关度发现"标题块刷屏, 新场景文档挤不进 top-k
  原因: MMR 对同质化标题块失效 (都是"高相关度发现")
  对策: 试点客户 20-50 份文档**单独索引** (不混全局库), 或按 doc_name 过滤

边界 2: 意图分类词表过拟合
  问题: "数据泄露处置"被 probe 误拦 (词表有"泄露")
  修复: probe 改组合特征 (已修 d7b78a0)
  对策: 新场景需复查分类词表 (领域专用词 vs 通用词)

边界 3: 短章节分块阈值
  问题: 制度章节 112-132 字符 < 200 阈值被丢弃
  修复: min_chars 200→50 (已修)
  对策: 分块阈值需按文档类型校准
```

### 框架复刻的正确姿势 (从验证得出)
```
1. 每客户单独索引库 (数据隔离 = 检索质量 + 数据安全)
2. 意图分类词表按场景复查 (防误伤)
3. 分块阈值按文档类型调 (制度/法规/手册不同)
4. 引用溯源自动生效 (不依赖文档格式)
```
