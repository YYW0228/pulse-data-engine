# 数据接入标准包 (Data Onboarding Kit) — v1.0

> 目的: 把"客户私有文档 → 可索引、可引用、可防护的知识"标准化、可复制、低人工
> 对应方法 D: 数据适配流水线 (替换成本从 50 天人工 → 2-5 天流水线 + 少量校验)

---

## 1. 客户需要提供什么

### 文档 (必填, 20-100 份)
| 格式 | 要求 | 说明 |
|------|------|------|
| PDF | 有文本层 (非纯扫描) | 扫描件需额外 OCR (见下) |
| Word (.docx) | 直接可解析 | 表格会自动提取 |
| Markdown / TXT | 直接可解析 | 最佳格式 |
| 扫描件 PDF | ⚠️ 需 OCR | 需安装 OCR 组件, 成本+时间 |

### 文档类型建议 (按场景)
- 合规问答: 制度文件、SOP、法规解读、内部政策
- 合同审查: 合同模板、历史合同(脱敏)、法律意见
- 内部知识: 产品手册、培训材料、FAQ

### 金标验收问题 (必填, 30-50 道)
客户提供真实业务问题 + 期望答案 (或答案出处)
```
示例:
  Q: 我们公司的数据出境需要什么审批流程?
  A: (出处: 《XX制度》第X章)
```

## 2. 我们返回什么

### 交付物清单
```
1. 索引报告 (index_report.md):
   - 解析成功率 (多少文件成功/失败/需OCR)
   - 分块数/字符数/覆盖率
   - 每个文档的分块统计

2. 索引数据库 (compliance.duckdb):
   - 512 维向量 HNSW 索引
   - 块重要性评分 (标题层级/实体密度)

3. 示例问答 (sample_qa.md):
   - 5 个金标问题的实际回答 + 引用溯源

4. 对抗样本报告 (adversarial_report.md):
   - 注入攻击 8 类 + 幻觉探测结果
   - 护栏是否守住

5. 验收基线 (acceptance_baseline.json):
   - 金标问题的检索命中率/引用覆盖率
```

## 3. 验收标准如何共同定义

### 三档验收
| 档位 | 标准 | 通过条件 |
|------|------|---------|
| P0 (必过) | 引用溯源 | 回答 100% 带引用, 引用真实存在于文档 |
| P1 (重要) | 金标命中 | 30-50 题中 ≥80% 检索到正确文档 |
| P2 (质量) | 人工抽检 | 客户抽 10 题, ≥8 题满意 |

### 验收流程
```
1. 客户提供文档 + 金标问题
2. 我们跑流水线 (解析 → 索引 → 对抗验证)
3. 输出交付物清单
4. 客户抽检 + 反馈 → 迭代 (限 2 轮)
5. 通过 P0+P1 → 交付; 未过 → 补数据或调参
```

## 4. 流水线命令 (内部)

```bash
# 1. 解析客户文档 (PDF/Word/md → 标准化块 JSONL)
uv run python -m scripts.doc_parser <客户文档目录> --out data/customer_docs

# 2. 索引 (含增量替换语义, 重复跑不重复)
uv run python -m scripts.compliance_index --source data/customer_docs --include-jsonl

# 3. 金标验收
uv run python -m scripts.eval_compliance --questions 客户金标.json

# 4. 对抗验证
uv run python -m scripts.adversarial_eval
uv run python -m scripts.injection_eval

# 5. 质量报告
uv run python -m scripts.answer_quality_eval
```

## 6. 已知限制 (诚实声明)

- 扫描件 PDF 需 OCR (当前未集成, 依赖客户提供文本层 PDF)
- Excel/PPT 未支持 (下版本)
- 图片/图表内容无法解析 (仅文本)
- 单文档 >200 页性能未测
