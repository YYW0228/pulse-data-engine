# 课程素材：为什么你的 AI 总在胡说八道？（RAG 原理解析）

## 一、核心论点 (TL;DR)
大语言模型（LLM）的“幻觉”并非模型故意撒谎，而是其基于概率预测生成看似合理但虚构内容的本质缺陷。检索增强生成（RAG）是解决此问题的核心技术，它通过引入外部真实文档作为上下文，强制 AI 基于事实而非猜测进行回答。本素材将深入解析 RAG 的两大阶段（摄入与查询），涵盖从文档解析、分块策略、嵌入技术到混合检索、重排序等关键优化手段。同时，课程将探讨如何构建评估体系（如 RAGAS）、实施安全护栏（防注入、权限控制）以及从基础 RAG 演进至 Agentic RAG 的实战路径，旨在帮助团队构建高可信、可验证且高效的 AI 应用系统。

## 二、章节摘要 (含时间戳)

1.  **AI 幻觉本质与 RAG 引入 (00:00 - 05:00)**
    *   阐述 AI 幻觉的成因：模型基于概率预测而非事实核查，导致生成虚构内容。
    *   介绍 RAG 的核心机制：检索外部知识库，将相关文档作为上下文注入，强制模型依据证据生成答案。
    *   强调“证据验证”的重要性：允许模型在信息不足时声明“无法回答”，并通过引用来源增强可信度。

2.  **RAG 架构基础与摄入阶段 (05:00 - 10:30)**
    *   拆解 RAG 流程：检索（Retrieve）、增强（Augment）、生成（Generate）。
    *   对比长上下文、微调等方案，明确 RAG 在动态大规模文档检索中的优势。
    *   深入摄入阶段：文档解析与 OCR 的关键性、元数据在过滤中的作用、分块（Chunking）策略（固定大小 vs 结构感知 vs 父子分块）。

3.  **检索优化与进阶策略 (10:30 - 15:00)**
    *   嵌入技术与混合搜索：利用向量语义距离结合关键词精确匹配（BM25），解决纯语义搜索的局限。
    *   检索参数调优：Top-K 的权衡（召回率 vs 噪音/成本）及重排序（Re-ranking）机制。
    *   场景化进阶策略：查询重写（模糊问题）、查询分解（多问题）、上下文压缩（文本过长）、迭代检索（证据缺失）。

4.  **系统评估、成本优化与安全 (15:00 - 20:00)**
    *   评估体系：分为检索评估（召回率、精确率）和答案评估（忠实度、相关性、引用正确性）。
    *   工具介绍：RAGAS、DeepEval、TrueLance、Arize Phoenix、OPIE 等框架的应用。
    *   降本增效：使用小模型、缓存、元数据过滤、调整 Top-K 及并发调用。
    *   优化原则：优先确保答案质量，再进行成本与延迟优化。

5.  **故障诊断、安全权限与架构演进 (20:00 - 25:00)**
    *   常见故障：陈旧索引、分块导致的残缺、Grounding 失败、权限过滤失效、模型忽略证据。
    *   安全组件：权限感知检索、不信任文档处理、提示注入防护、敏感数据隔离及审计。
    *   架构演进路线：从基础 RAG 到迭代 RAG，再到 Agentic RAG（模型自主决策检索）及全功能 Agent。

6.  **实战案例与总结 (25:00 - 28:25)**
    *   实战案例展示：基于 ArXiv 论文的完整架构（Docling 摄入、PostgreSQL/OpenSearch 存储、本地 LLM、FastAPI/Gradio 接口、Redis 缓存、OPIE 可观测性）。
    *   总结：RAG 结合 AI Agent 能显著提升相关性与可验证性，但需配合高质量数据源、精细检索策略及完善的评估体系。

## 三、关键概念卡片

| 概念名称 | 定义与核心逻辑 | 应用场景/注意事项 |
| :--- | :--- | :--- |
| **幻觉 (Hallucination)** | AI 模型基于概率预测生成的看似合理但完全虚构或错误的事实。 | 需通过 RAG 引入外部证据进行约束，防止模型“自由发挥”。 |
| **RAG (检索增强生成)** | 先检索外部知识库中的相关文档，将其作为上下文注入 LLM，生成基于事实的回答。 | 适用于动态、大规模文档集合的实时检索需求，优于静态微调。 |
| **分块 (Chunking)** | 将长文档切割成较小片段的过程，平衡上下文完整性与检索效率。 | 需根据文档类型选择策略（如结构感知分块优于固定大小），避免语义断裂。 |
| **嵌入 (Embedding)** | 将文本转化为高维数值向量，使语义相似内容在向量空间中距离更近。 | 支持语义搜索，但需结合关键词搜索以弥补对精确术语匹配的不足。 |
| **混合搜索 (Hybrid Search)** | 结合关键词搜索（精确匹配）和语义向量搜索（意图理解）的检索策略。 | 适用于既需要精确代码/术语匹配，又需要理解用户模糊意图的场景。 |
| **重排序 (Re-ranking)** | 对初步检索出的大量候选片段进行二次排序，筛选最优质片段输入 LLM。 | 用于平衡相关性、延迟与成本，避免将噪音片段送入生成模型。 |
| **Top-K** | 检索阶段设定的参数，指每次查询返回的最相关片段数量。 | 需实验调优：过少遗漏证据，过多增加噪音和 Token 成本。 |
| **查询重写 (Query Rewriting)** | 利用小模型将用户模糊的原始问题改写为更明确、适合检索的语句。 | 针对用户提问不清晰、缺乏关键词的场景使用。 |
| **迭代检索 (Iterative Retrieval)** | 首轮检索未找到足够证据时，基于当前回答缺失部分再次发起检索。 | 用于处理复杂问题或证据分散的场景，直到证据充足。 |
| **忠实度 (Faithfulness)** | 评估生成的答案是否严格基于提供的检索证据，未引入外部未证实信息。 | RAG 系统的核心评估指标之一，直接衡量抗幻觉能力。 |
| **提示注入 (Prompt Injection)** | 攻击者通过构造特殊输入，诱导模型忽略系统指令或执行非预期操作。 | 需通过权限感知检索、不信任文档处理及严格的输入过滤进行防护。 |
| **Agentic RAG** | 引入智能体层，让模型自主判断是否需要检索、检索内容及何时停止。 | 解决复杂推理和行动需求，是 RAG 向全功能 Agent 演进的方向。 |

## 四、金句 (中英对照)

1.  **关于幻觉本质**
    *   中文：AI 产生“幻觉”并非模型在撒谎，而是它基于概率预测生成了看似合理但虚构的内容。
    *   English: AI hallucination is not the model lying; it is the model generating plausible but fabricated content based on probability prediction.
2.  **关于 RAG 价值**
    *   中文：RAG 的核心在于让 AI 基于事实而非猜测进行回答，通过引入外部真实文档作为上下文。
    *   English: The core of RAG is to enable AI to answer based on facts rather than guesses by introducing external real documents as context.
3.  **关于优化原则**
    *   中文：必须先确保答案质量满意，再进行成本和延迟优化。
    *   English: You must ensure answer quality is satisfactory before optimizing for cost and latency.
4.  **关于证据验证**
    *   中文：RAG 仅提供证据而非真理或行动，需结合 Agent 系统解决复杂推理和行动需求。
    *   English: RAG provides evidence, not truth or action; it must be combined with Agent systems to solve complex reasoning and action needs.
5.  **关于分块策略**
    *   中文：错误的解析无法通过后续步骤修复，结构感知分块优于盲目的固定长度切割。
    *   English: Incorrect parsing cannot be fixed by subsequent steps; structure-aware chunking is superior to blind fixed-length cutting.

## 五、与主线课程/本司架构的映射

本段内容紧密贴合我司当前的 RAG 技术架构与研发规范，具体映射如下：

1.  **架构组件对应**：
    *   **向量检索**：本司架构采用 **DuckDB VSS** 作为向量存储引擎，替代传统方案，利用其高性能与本地化特性。
    *   **嵌入模型**：统一使用 **bge-small-zh** 模型进行文本向量化，确保中文语义检索的准确性与效率。
    *   **生成模型**：底层生成能力基于 **DeepSeek** 大模型，利用其强大的逻辑推理与长上下文处理能力。

2.  **安全与审计机制**：
    *   **引用验证门禁**：我司系统严格执行“有引才答”原则，所有生成内容必须附带来源引用，否则视为无效回答，直接阻断幻觉输出。
    *   **llm_audit 审计不变量**：系统内置 `llm_audit` 模块，对生成过程进行全链路审计，确保数据隔离、权限控制及操作日志的可追溯性，符合企业级安全合规要求。

3.  **演进路线对齐**：
    *   当前架构已具备从基础 RAG 向 **Agentic RAG** 演进的基础，未来将结合 Agent 系统，赋予模型自主判断检索策略及执行复杂任务的能力，同时保持严格的 Grounding（落地/锚定）机制。

4.  **评估体系落地**：
    *   我司在研发流程中已集成类似 **RAGAS** 的评估理念，重点关注“忠实度”与“引用正确性”，并通过自动化测试确保每次迭代的质量不降级。
