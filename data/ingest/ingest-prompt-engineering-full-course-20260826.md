# 提示工程全课程：从基础指令到智能体架构实战

## 一、核心论点 (TL;DR)
提示工程（Prompt Engineering）本质上是“自然语言编程”，其核心在于通过精确的指令（角色、受众、语气、格式、约束）引导大型语言模型（LLM）输出高质量结果，而非依赖模型自行猜测。课程从基础指令优化（如少样本提示、思维链）进阶到复杂策略（如提示词链、自我评估、访谈式交互），并深入探讨了模型参数（如温度值）对确定性与创造性的控制。最终目标是构建可落地、可验证的自动化工作流，将模糊的自然语言转化为结构化的行动指令，以适应 Agent 时代的需求。

## 二、章节摘要 (含时间戳)

1.  **指令质量与效率基石 (00:00 - 08:00)**
    *   通过对比模糊指令与结构化指令（角色、受众、CTA）的案例，阐明“坏提示词”导致模型猜测，而“好提示词”能产出精准结果。
    *   定义提示工程为用自然语言替代代码的编程方式，强调在 Agent 时代，提示词需从“获取文本”转向“指导行动”。
    *   提出解决方案：利用语音输入工具（如 Whisper Flow）替代手动打字，自动处理标点、去噪并格式化列表，大幅提升编写效率。

2.  **LLM 原理与核心构建要素 (00:00 - 05:30)**
    *   揭示 LLM 本质是“文本预测模型”，无内置记忆，上下文由工具注入。
    *   区分“命令（Commanding）”与“引导（Steering）”：前者仅给任务，后者通过具体约束（角色、受众、语气、格式）控制输出。
    *   构建高质量 Prompt 的四大要素：角色 (Role)、受众 (Audience)、语气 (Tone)、格式/输出要求 (Format)。

3.  **高级技巧：少样本与思维链 (00:00 - 12:30)**
    *   **结构化与隔离**：使用分隔符组织提示词，并通过开启新会话（Context Isolation）避免历史对话干扰。
    *   **少样本提示 (Few-Shot Prompting)**：提供输入 - 输出示例对，让模型模仿模式，特别适用于格式化和分类任务。
    *   **思维链 (Chain of Thought)**：要求模型先展示逐步推理过程，显著降低逻辑和数学任务的错误率。
    *   **结构化输出**：强制模型输出 JSON、XML 等机器可读格式，便于程序化处理。

4.  **约束控制与迭代优化 (00:00 - 16:00)**
    *   **负面指令 (Negative Instructions)**：明确“不要做什么”（如禁止特定词汇、禁止道歉）往往比正面指令更有效。
    *   **迭代优化 (Iterative Refinement)**：将提示词编写视为对话过程，基于初步回复进行多轮调整（如“更短”、“更正式”），而非一次性完美。
    *   **访谈式提示法 (Interview-Style Prompting)**：让模型扮演面试官主动提问，收集用户遗漏的背景信息（受众、动机等），确保上下文完备。

5.  **系统架构与高级策略 (00:00 - 06:30)**
    *   **系统 vs 用户提示词**：系统提示词定义底层身份与规则（不可见），用户提示词处理具体任务。
    *   **提示词链 (Prompt Chaining)**：将复杂任务拆解为连续步骤，以前一步输出作为后一步输入，实现分步验证。
    *   **自我评估 (Self-Evaluation)**：让模型自我批判，关键技巧是假装内容由“人类”撰写，以避免模型的自我偏袒。
    *   **参数调整**：提及 Temperature 参数对随机性和创造性的控制（视频在此处截断）。

6.  **综合实战与最佳实践 (00:00 - 结尾)**
    *   **温度机制**：低温度=高确定性（适合代码/事实），高温度=高创造性（适合头脑风暴），需根据结果动态调整。
    *   **常见错误修正**：针对指令模糊、任务过载、上下文不足、格式忽略、记忆误区提供具体修正方案。
    *   **工具推荐**：再次强调使用语音输入工具（如 Flow）替代打字，提升长提示词编写效率，适应开发者及多智能体协作场景。

## 三、关键概念卡片

| 概念名称 | 英文术语 | 核心定义 | 应用场景 |
| :--- | :--- | :--- | :--- |
| **提示工程** | Prompt Engineering | 使用自然语言（文本或语音）向 LLM 下达指令，定义任务、角色、格式和约束的过程。 | 所有与 LLM 交互的场景，将自然语言转化为可执行的指令。 |
| **引导 vs 命令** | Steering vs. Commanding | **引导**：提供具体约束控制输出；**命令**：仅告知任务，细节交由模型决定。 | 需要高质量、可控输出的场景应使用“引导”。 |
| **少样本提示** | Few-Shot Prompting | 提供多个“输入 - 输出”示例对，让模型推断模式并模仿。 | 需要特定格式、处理边缘案例或分类任务时。 |
| **思维链** | Chain of Thought | 要求模型在给出答案前先进行逐步推理（Step-by-step reasoning）。 | 逻辑推理、数学计算、复杂规划类任务。 |
| **负面指令** | Negative Instructions | 明确列出“不要做什么”（如禁止特定词汇、语气）。 | 需要严格规避某些内容或风格时，比正面指令更有效。 |
| **访谈式提示** | Interview-Style Prompting | 让模型主动提问以收集缺失的背景信息，待信息完备后再生成。 | 用户信息不全，需挖掘隐含需求时。 |
| **提示词链** | Prompt Chaining | 将复杂任务拆解为多个连续步骤，前一步输出作为后一步输入。 | 复杂工作流，需分步验证中间结果时。 |
| **温度值** | Temperature | 控制模型输出随机性和创造性的参数。 | 调整输出风格：低温求稳（代码/事实），高温求新（创意）。 |
| **结构化输出** | Structured Output | 强制模型输出 JSON、XML、表格等机器可读格式。 | 需要程序直接解析、存入数据库或 API 调用时。 |
| **上下文隔离** | Context Isolation | 开启新对话会话，防止旧历史干扰当前任务。 | 需要专注单一任务，避免信息污染时。 |

## 四、金句 (可作课程引用，中英对照)

1.  **关于指令本质**
    *   CN: 提示工程不是魔法，而是“自然语言编程”。差异不在于模型本身，而在于指令的方式。
    *   EN: Prompt Engineering is not magic; it is "natural language programming." The difference lies not in the model itself, but in the way you instruct it.

2.  **关于引导策略**
    *   CN: 不要只是告诉模型“做什么”，要告诉它“怎么做”以及“不做什么”。
    *   EN: Don't just tell the model what to do; tell it how to do it and what *not* to do.

3.  **关于迭代思维**
    *   CN: 提示词编写应被视为一场“对话”，而非一次性的尝试。
    *   EN: Treat prompt writing as a "conversation," not a one-shot attempt.

4.  **关于自我评估**
    *   CN: 在让模型自我评估时，假装内容是由人类撰写的，以避免模型的自我偏袒。
    *   EN: When asking the model to self-evaluate, pretend the content was written by a human to avoid self-indulgence bias.

5.  **关于 Agent 时代**
    *   CN: 在智能体时代，提示词需从“获取文本”转向“指导行动”。
    *   EN: In the Agent era, prompts must shift from "getting text" to "guiding action."

## 五、与主线课程/本司架构的映射

本段素材中的核心概念可直接映射至我司当前的 RAG（检索增强生成）架构设计与落地实践中：

1.  **结构化输出与 API 集成**
    *   课程中强调的**结构化输出 (Structured Output)** 和 **JSON Schema** 技术，是我司 RAG 架构中连接检索模块与生成模块的关键。在调用 **DeepSeek** 生成回答时，强制模型输出符合特定 Schema 的 JSON，确保后端程序能直接解析并渲染前端卡片，避免模型生成 Markdown 或闲聊文本导致解析失败。

2.  **上下文管理与隔离**
    *   课程提到的 **上下文隔离 (Context Isolation)** 策略，对应我司在构建长文档问答时的会话管理机制。通过在新会话中注入特定的系统提示词，防止用户历史闲聊干扰当前的专业检索任务，确保 **bge-small-zh** 向量检索召回的内容能精准匹配当前查询意图。

3.  **提示词链与多步推理**
    *   **提示词链 (Prompt Chaining)** 理念直接应用于我司的复杂查询处理流程。当用户提出复杂问题时，系统将其拆解为“检索相关文档” -> “提取关键实体” -> “生成回答” -> “引用验证”等多个步骤。每一步的输出作为下一步的输入，利用 **llm_audit** 审计不变量对中间步骤进行质量把关。

4.  **自我评估与引用验证门禁**
    *   课程中的 **自我评估 (Self-Evaluation)** 技巧，与我司的 **引用验证门禁** 高度契合。在生成最终回答前，系统可让模型（或专门的评估模型）对生成的内容进行“自我批判”，检查是否包含未检索到的幻觉内容。结合 **llm_audit** 审计不变量，确保输出内容的准确性、一致性和安全性，防止模型产生“自我偏袒”或过度宽容的偏差。

5.  **语音输入与开发效率**
    *   课程推荐的 **Whisper Flow** 等语音输入工具，对于我司内部开发团队编写复杂的 System Prompt 和 User Prompt 具有极高价值。在快速迭代 RAG 策略或调试 DeepSeek 生成逻辑时，利用语音输入能显著降低编写长提示词的时间成本，提升研发效率。
